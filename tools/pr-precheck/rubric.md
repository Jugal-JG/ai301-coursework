# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff stays inside the plan | The diff's changed files and hunks, read against the plan's in-scope and not-in-scope statements, its named files, its approach steps, and any deviation note. | Pass if every changed file and hunk is covered by the plan's in-scope work or by a deviation note, nothing the plan marks out of scope appears (a new option or flag, a rename pass, a rewrite, a migration), and every approach step the plan promised appears in the diff or is stated as deferred in the plan's notes or the description. Fail if the diff contains work the plan never named (even a small adjacent change like rewording unrelated help text or adding a setting), or silently omits a promised step. A deferral that the plan or the description states with a reason is not a fail. | required |
| Description matches the diff | The PR description's claims ("implements the plan exactly", "no changes beyond the fix", "docs now document X", "tests added") read against the diff's actual files and hunks. | Pass if every claim in the description about what changed is true of the diff, and the Changes list covers what the diff does. Fail if the description claims something the diff does not contain (a docs update that is not in the diff, tests that were not added), claims fidelity ("exactly as planned", "no functional changes outside X") that the diff contradicts, or leaves out a change the diff makes. | required |
| Test evidence is decisive | The test evidence (commands and output), read against the plan's test plan and the repro steps. | Pass if the evidence re-runs the plan's repro on the changed path and shows output that differs before and after the fix, and it covers each failure mode or case the plan's test plan names, or the plan or description states which one was left out and why. Fail if the evidence is only a claim ("tested locally", "works on my machine", "tests pass") with no named command or output, if it exercises a path the fix did not change (a control or unchanged case), if it omits a failure mode the plan's test plan named without saying so, or if an added test does not exercise the fixed behavior. | required |
| Repo checks were run and reported | The test evidence and the Testing section, read against the checks the repo's PR template and contribution docs name (test, lint, typecheck commands). | Pass if the evidence shows each check the repo names was run with its real result, or states plainly that one was not run or failed and why. A failing check reported honestly passes. Fail if a named check is neither shown nor mentioned, or the Testing section ticks a box the evidence does not support. Pass by default when the repo names no checks. | preferred |
| Diff is free of debris | The diff's added lines and hunks, and the commit list. | Pass if the diff contains only the change: no debug prints or logging added for debugging, no commented-out code, no dead or unused functions or imports added, no re-indent, reformat or reordering hunks that change no behavior, and no unrelated hunks. Fail if any of those appear, even beside a correct fix. A mechanical hunk that the fix needs (an import the new code uses) is not debris. | required |
| Template and disclosure asks are met | The PR description, read against the repo-facts block's PR-template line and contribution-policy line (live: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`). | Pass if every section or item the repo's template asks for is filled with real content (issue reference, checklist, changelog entry when the template asks for one and the diff should carry it), the diff carries any file the repo's stated policy requires, and, when the repo's policy explicitly requires disclosing AI use, the description states plainly that AI was used. Fail if the stated template sections are visibly left empty or ignored, a required changelog or test file is missing from the diff, or the policy requires AI disclosure and the description is silent. Pass by default when the repo states no template and no AI policy. Every package is treated as AI-assisted work. | required |
| Commit history reads as a change | The commit list's messages, read against the repo's commit convention when it states one. | Pass if the commit messages describe the change. Fail only if every commit is a placeholder ("wip", "fix", "misc cleanups while debugging") and the repo states a convention. | preferred |

## Verdict rule

Accept only if every `required` check grades `pass`. Any `required` check graded `fail` or `unclear` makes the verdict `reject`: a PR I cannot verify from the package is not ready to submit. `preferred` checks are reported in the evidence lines but never change the verdict. An honestly disclosed shortfall can still be accept: if the plan or the description says plainly what was deferred and why, that is not a fail on the plan-fidelity or test checks. A terse PR that passes every required check is accept, and a polished PR that fails one required check is reject.
